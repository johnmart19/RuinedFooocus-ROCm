# Chat storage and cleanup

RuinedFooocus stores private chat artifacts under `cache/embeds` in the project:

- `logs`: native llama-server diagnostic logs, which can include failed tool data.
- `sources`: downloaded reference documents used for chat retrieval.
- `images`: new images generated by the built-in chatbot, including their prompt metadata.

Chat transcripts, vision feedback and automatic conversation summaries remain in
memory; this change does not enable automatic transcript logging. The image
browser excludes this directory so it does not copy those prompts into its own database.
Models, projectors, runtime binaries and configuration stay in their existing folders.

To clear these artifacts, close RuinedFooocus and its browser tabs, then delete
the contents of `cache/embeds`. Closing the app also releases in-memory chat and
retrieval state. The directory is recreated when needed. Close the app first:
Windows may prevent removal of a runtime log while the model is still loaded.

Alternatively, enable **Also delete cached chat data when clearing** beneath the
Chat bots message field, then use the existing clear-chat control. This option
clears the shared local cache (including chatbot images), unloads the chat model,
and resets after use. Other users' local cached artifacts are included; it does
not delete their Open WebUI database or erase other browser tabs' visible history.
Leave the option unchecked to clear only the current conversation. Cleanup runs
on the generation worker, so it waits for active work instead of unloading mid-request.

Vision reviews are temporary context for one follow-up prompt iteration. New
images replace previous reviews; old reviewer text and image bytes do not enter
conversation summaries. The original displayed chat remains available until cleared.

Known legacy `cache/llama.cpp/server-*.log` files and files directly under
`cache/embeds` are organized into its subfolders on the next native-model load or
retrieval initialization. Files from the earlier `outputs/chats` layout are also
moved into `cache/embeds`, preserving their category and relative paths.
Locked files are deferred until their runtime exits. Old generated images cannot
be reliably distinguished from ordinary image generations and are not moved or
deleted automatically; their embedded prompts remain with those images.

Open WebUI owns its separate database and browser storage. Clear its conversations
in Open WebUI too. Images generated through its API tools remain ordinary API
outputs, because the image endpoint does not know which client conversation owns
them. External terminal captures, exported chats, backups and third-party caches
are also outside RuinedFooocus's chat directory.
